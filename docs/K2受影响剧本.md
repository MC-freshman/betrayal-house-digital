## 1. 判定标准（与脚本同口径）

**数据来源**

- 数据层：`haunt_rules.get_haunt_rule_override(n)`（n=1..70）返回的规则字典 —— 70 本全有。
- 代码层：`haunts/haunt_XX_*.py` 模块源码（`check_victory` / `available_actions` / `perform_action` / 常量表）。

**「引用」**：规则字典里任一字符串值等于四房 id 之一（`key_rooms` / `actions.rooms` / `tracks` / `monsters[].room_ids` / `tokens` 等），或 handler 源码里出现该 id 的字符串字面量。

**「是否为胜利必需房」**

| 判定 | 含义 |
|---|---|
| **是** | 房间出现在 `win_conditions`；或出现在**结束对局的那个行动**的 `rooms` 里；或 handler 把该房间写死为胜利前置（数据层没声明也算） |
| **间接** | 房间只出现在 `key_rooms`、前置搜寻/装备/生成链、非终局 `actions.rooms`、`tracks` 标签或 handler 常量里 —— 影响路径与难度，但**不是**胜利的硬条件 |
| **无关** | 该剧本完全不引用这四间房（`70 - 32 = 38` 本） |

一本剧本引用多间房时，本表取**最强**判定（是 > 间接）。

**两处人工判定**（脚本里以 `TERMINAL_ACTIONS` / `HANDLER_REQUIRED` 显式登记，逐本对过 handler）：

1. **#43 阴影聚集 · tower**：终局动作 `ritual_roll` 只允许在 `RITUAL_ROOMS`（balcony / garden / graveyard / patio / **tower**）执行，且每间只能用一次、目标 = `min(玩家数, 5)` —— 5–6 人局必须把 5 间全用一遍，tower 是硬条件。
2. **#34 疯狂世界 · vault**：规则字典里 `vault` 只在 `key_rooms`，但 handler 的 `lock_up`（关押俘虏，推进 `captives_locked`）**只在保险库可用**且要求库门已开（`haunt_34_mad_world.py` L250 `available_actions` / L271 `perform_action`）—— 数据层漏写、代码层写死。

> 除这两处外，其余 30 本的四房引用都落在「多房间备选 / 前置搜寻 / 生成位 / key_rooms 提示」上：**没有一本把四房中的某一间作为唯一胜利位置**。K2 补上障碍后，这 32 本的**可解性不变，难度与路径变**。

## 4. 补 `BARRIER_SPECS` 后的优先回归顺序

| 级别 | 剧本号 | 理由 |
|---|---|---|
| **P0 必回归** | **34、43** | 唯一的「胜利必需房」：vault 与 tower 加了障碍后，`lock_up` / `ritual_roll` 的可达性直接决定胜负 |
| **P1 高** | **15、24、37、48、68、70** | 房间承载硬交互：装备生成位（15）、蝙蝠起始点（24）、圣印落点（37）、开锁门槛（48）、开场移除房间（68）、唯一搜寻点（70） |
| **P2 常规** | 1、5、7、9、13、16、17、18、19、23、25、27、29、30、31、32、35、36、44、51、55、58、59、67 | 只影响路径长度/难度（多房间备选、提示房、暮色/日照判定），按冒烟回归 186 条中对应剧本用例即可 |

回归判据（K2 落地后执行，不在本轮范围）：186 条黄金重冻 + 2310 局胜率基线重建，并逐条比对 P0/P1 剧本的回合数与胜负分布。
